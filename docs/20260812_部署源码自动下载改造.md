## 一、背景与目标

之前部署源码需要人工 SFTP 上传到目标机 `/opt/`，或靠手册步骤里写 `wget/curl`。本次改造让部署平台**识别源码地址类型并自动下载到目标机可配置路径**，探查前完成，无需人工传码。

**目标机环境**：`39.106.16.32`（root/A892wYxn，端口 22，约 941MB 内存，无 git，有 curl/wget/python3，Docker 可用，GitHub/HTTPS 可访问）。

## 二、核心设计

### 源码来源识别（4 类）

| 来源类型 | 判别 | 行为 |
|---------|------|------|
| `git` | 地址含 `github.com / gitee.com / gitlab.com / gitcode.com / jihulab.com / .git` | 目标机有 git → `git clone --depth 1`；无 git → curl 下载仓库 zip 解压 |
| `http` | `http(s)://` 且非 git 域名 | curl 下载压缩包（zip/tar.gz）并解压 |
| `offline` | `offline://` 或 `offline:` 前缀 | 走离线仓库（复用离线仓库功能页） |
| `local` | 本地路径（`/data/xxx` 等） | 不下载，直接引用 |

### 在线 git 的 zip 下载地址归一化（`_git_zip_url`）

- GitHub：`https://github.com/{owner}/{repo}` → `https://codeload.github.com/{owner}/{repo}/zip/refs/heads/master`
- Gitee：→ `https://gitee.com/{owner}/{repo}/repository/archive/master.zip`
- 已是 `.zip` 的地址直接使用

### 下载目标路径（`resolve_download_path`）

- 用户填 `artifact_download_path` → 用之
- 未填 → 默认 `/data/aiops-deploy/<计划名>`（计划名做安全化处理）

### 幂等

- 目标路径已存在且含 `docker-compose.yml / docker-compose.yaml / compose.yaml` → 跳过下载
- git 目录非空且已有内容 → 执行 `git pull --ff-only` 增量更新
- `artifact_auto_download=False` → 关闭自动下载

## 三、改动清单

### 1. CONTRACT.md（第十一章 11.1 / 11.4）

新增字段：

| 字段 | 说明 |
|------|------|
| `artifact_path` | 扩展语义：支持①资产本地路径 ②HTTP 下载地址 ③Git 仓库地址 |

## 六、专业名词学习

- **CI / CD 源码拉取（Source Fetch）**：部署前从 SCM（Git）或制品库自动获取代码的环节
- **幂等下载（Idempotent Fetch）**：重复执行不产生副作用，已存在则跳过/增量更新
- **Codeload**：GitHub 提供免鉴权的源码打包下载子域名（codeload.github.com）
- **IPFS 式解包**：不限
- **L4/L5 层能力**：AI 环境感知（探查）→ 自主执行（自动下载/部署）→ 自适应适配 → 报告
