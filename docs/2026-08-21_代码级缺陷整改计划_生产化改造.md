## 二、P0-A　凭据清仓（最紧急）

### A1. 仓库已跟踪文件含明文生产/内网凭据 —— 致命

**现状（已取证）**：
- `MEMORY.md` **被 git 跟踪**，内含大量明文凭据：
  - 虚机 `11.0.1.134 (root/123456)`（`MEMORY.md:69`）
  - Docker Registry `admin/admin123` + htpasswd（`MEMORY.md:728,739`）
  - PostgreSQL `postgresql://aiops:aiops-secret@127.0.0.1:5432/aiops`（`MEMORY.md:809,1048`）
  - 登录 `admin/admin123`（`MEMORY.md:1047`）
- 其它被跟踪明文：`app/config.py:40`（默认 PG 连接串含 `aiops-secret`）、`app/services/log_query_service.py:218`（内网 IP + root/123456）、`deploy/README.md:16`、`docs/架构图自动生成_任务接管文档.md:77`。

**根因**：AGENTS.md 要求维护 `MEMORY.md` 作为会话记忆 → 被持续 git 跟踪 → 明文凭据随提交进入仓库历史。

**改造步骤**：
1. `MEMORY.md` 加入 `.gitignore`，并从工作区剥离为本地私有笔记；在 AGENTS.md「会话记忆机制」补充「**不得在记忆文件中记录明文密码/token，一律写 `见 .env / Secret Vault`**」。
2. 用 `git filter-repo` 或 BFG 清理 `MEMORY.md` 及其它含凭据文件的**历史**（先备份仓库，见高危审批）。
3. **轮换全部受影响密码**：虚机 root、Docker Registry admin、Postgres、admin 登录。（按 AGENTS 铁律：先列清单等确认）
4. 落地防回归：CI 增加 **gitleaks / trufflehog 密钥扫描门禁**（不复用 `|| true` 的假通过）。

**验收标准**：
- [ ] `git grep -l "123456\|admin123\|aiops-secret"` 对仓库 git 树为空。
- [ ] `MEMORY.md` 不再被 `git ls-files` 列出。
- [ ] CI 新增强制密钥扫描，命中即红。

## 三、P0-B　桩功能与算法真实性

### B1. Granger 因果检验 —— ✅ 已完成（爸爸选方案 B：真实现）

**现状**：`app/routers/granger.py` 原为纯桩（仅 `/status`）。

**已实施（2026-08-21）**：
- `app/services/rca_algos_service.py` 新增 `run_granger(db, asset_id, metric_a, metric_b, hours, maxlag)`：
  - `_asset_metric_series()` 按时间升序取单指标序列；`_align_series()` 按**时间戳交集**对齐两条序列；
  - 基于 `statsmodels.tsa.stattools.grangercausalitytests`（`ssr_ftest`）**双向**检验 a→b / b→a，输出每个滞后的 F、p、95% 显著性 + 最佳滞后 + 结论。
- `app/routers/granger.py` 新增 `GET /granger/analyze?asset_id=&metric_a=&metric_b=&hours=&maxlag=`，保留 `/status`。
- 已验证：合成数据 a(噪声)→b(带滞后响应)，**a→b p≈0.000 显著、b→a p>0.05 不显著**（方向判定正确）。
- 修复过程发现的真实 bug：gct 的响应/原因列语义与标签曾反向，E2E 测试捕获后修正。

**验收 ✅ 已达成**：`/granger/analyze` 返回该方法的结果结构（`directions`、`best_p_value`、`conclusion`、`method`）；`tests/test_drain_granger.py` 有 `TestRunGrangerE2E` 覆盖端到端方向性。

### B2. iDICE / LogClu（Drain）—— ✅ 已完成

**现状**：`rca_algos_service.py:116 run_idice` 为皮尔逊相关；`app/routers/drain.py` 为定长 token 简化版。

**已实施（2026-08-21）**：
- **iDICE**：保留真实相关归因作为 v1，但**诚实标注**——`run_idice` 返回新增 `method: "idice-v1: target-correlated-influence"` 与 `note`（明示该结果属"伴随/相关"证据而非控制后的因果结论），杜绝名不副实。
- **Drain**：`app/routers/drain.py` 升级为**标准树形 Drain**：
  - 索引树按深度逐 token 匹配（不再是 O(n) 线性扫描）；
  - **变长/类型 token** 归一为占位符：IPv4→`<IP>`、十六进制→`<HEX>`、数字→`<NUM>`、路径→`<PATH>`、成对括号/引号整块合并；
  - 叶节点按相似度阈值合并并通配差异 token；
  - 新增 `depth`/`similarity_threshold` 参数。
- 已验证：`["ERROR 连接失败 127.0.0.1 33 timeout", ...3条]` 归并为 `ERROR 连接失败 <IP> <NUM> timeout`；`cpu 80/cpu 90` 因 `<NUM>` 归一正确归并。

**验收 ✅ 已达成**：`run_idice` 返回含 `method`/`note`；Drain 输出含 `<IP>/<NUM>` 类型占位符；`tests/test_drain_granger.py` 覆盖两者。

### 测试补充（✅）
- 新增 `tests/test_drain_granger.py`：**10 用例全部通过**（Drain 树形聚类 + Granger 对齐/方向/E2E）。
- `test_core_algorithms.py` 26 用例 + 新 10 用例 = **36 passed**，无回归。

## 五、P1-B　CI 门禁「真生效」

**现状（已取证）**：
- 覆盖率门槛 `--cov-fail-under=25`（`ci.yml:72`、`coverage-gate.yml:18`、`unit-test.yml:36`）高于实测总体 ~20.4% → 门禁名不副实。
- `security-scan.yml:26`：`pip-audit ... 2>&1 || true` → CVE 命中永不红。
- `db-migration-check.yml:17`：仅跑 `check_migrations.py`（无 `--full`），`tools/check_migrations.py:108-113` 无 `--full` 时只 `check_tree()`（数版本数），**不查同步**。
- Makefile `test` 目标 `--cov-fail-under=20` 与 CI 25 不一致。

**改造**：
1. 覆盖率：先统一口径（本地 make test == CI），门槛先降到 PR 实测通过线（如 20）并加红，后续随测试补齐逐步抬到 40/60。
2. security-scan：去掉 `|| true`，`pip-audit` 红则 job 失败；新增 gitleaks 密钥扫描（承接 A1）。
3. db-migration-check：加 `--full`（跑 `check_sync()`），让「schema 与模型漂移」在 CI 拦截。
4. 单元测试：给 `test_api_integration.py` 等补真实断言覆盖，逐步提升覆盖率的**核心服务**（告警/部署/RAG/工作流）优先。

**验收**：
- [ ] 覆盖率 job 在真实 PR 上可「绿 = 达到声明值、红 = 未达」，且数字与本地一致。
- [ ] `pip-audit` 命中 CVE 时 job 变红；密钥扫描命中时变红。
- [ ] 模型/迁移漂移能被 `db-migration-check` 拦下。
