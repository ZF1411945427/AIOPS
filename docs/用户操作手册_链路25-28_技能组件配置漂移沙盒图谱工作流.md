# AIOps 用户操作手册 — 链路25-28：技能组件 & 配置漂移 & 沙盒知识图谱 & 工作流引擎

> **适用角色**：运维工程师、SRE、知识管理员、AI 管控员
> **前置条件**：已登录系统，拥有相关菜单权限
> **预计耗时**：约 25-35 分钟

---

## 概述

本手册覆盖四条链路（对应系统较新版本新增/重组的核心能力）：

- **链路25**：技能与组件（技能中心：技能库/技能市场/组件方案/组件商店）
- **链路26**：配置漂移检测（配置基线 → 漂移检测 → AI 评估）
- **链路27**：沙盒管控 与 知识图谱推理
- **链路28**：SOP 工作流引擎（工作流模板 + 工作流执行）

> **链路25 技能组件**　①技能库 → ②技能市场 → ③组件方案 → ④组件商店(部署/体检)
> **链路26 配置漂移**　①建基线 → ②检测漂移 → ③AI评估 → ④状态处理
> **链路27 沙盒图谱**　①沙盒策略 → ②决策测试 → ③图谱影响/根因/推荐推理
> **链路28 工作流**　①建模板 → ②触发执行 → ③节点确认 → ④查看结果

---

# 链路25：技能与组件

> 入口：**Agent 管理 → Agent 运维 → 技能中心**（key=`skills`，path=`/skills`）。技能中心为 Tab 容器，含「技能库 / 技能市场 / 组件方案 / 组件商店」四个 Tab。

## 第一步：技能库管理

### 操作页面
**侧边栏** → **Agent 管理** → **Agent 运维** → **技能中心** → **技能库** Tab

### 操作步骤

1. **查看技能列表**
   - 顶部统计卡显示：技能总数 / 启用 / 禁用 / 累计调用
   - 表格列出每个技能：名称、版本、分类、风险等级、来源、状态

2. **新建技能**
   - 点击「+ 新建技能」按钮
   - 填写：技能名（唯一，作为 Agent 调用 `use_skill` 的入参名）、描述、版本/作者/License、分类/风险/依赖工具、关键词、`SKILL.md` 内容
   - 保存（新建走 POST，编辑走 PUT）

3. **导入技能包**
   - 点击「⬆️ 导入技能包」→ 选择 `.zip` 技能包 → POST `/api/skills/import`

4. **执行技能（调用）**
   - 点击技能行「▶️ 执行」→ 输入目标/参数 → POST `/api/skills/{id}/run`
   - 执行结果写入调用审计（可在下方「执行审计」面板查看）

5. **启用/禁用 / 编辑 / 导出 / 删除**
   - 行内开关切换启用状态；「详情 / 编辑 / 导出 / 删除」按需操作
   - 注：内置（builtin）技能删除时实际为禁用

### 看到什么
- 技能列表与统计卡
- 执行后可在执行审计面板看到调用记录与结果

## 第四步：组件商店（一键部署 + 体检）

### 操作页面
**Agent 管理** → **Agent 运维** → **技能中心** → **组件商店** Tab

### 操作步骤

1. **浏览组件目录**
   - 按分类（数据库/缓存/消息/Web/可观测）+ 关键词搜索 → GET `/component-market/api/catalog`

2. **一键部署**
   - 组件卡片「一键部署」→ 弹窗选择：目标机 Asset / 部署方式（传统 native / Docker / K8S-Helm / 高可用 ha）/ 命名空间·Release / 部署路径 / 网络代理

> 入口：**资源管理 → 资产管理 → 配置漂移检测**（key=`config-drift`，path=`/config-drift`）。含「漂移记录 / 配置基线 / 采集模板」三个 Tab。

### 操作步骤

1. **新建基线**
   - 点击「＋ 建立配置基线」→ 弹窗选择：目标资产、配置项 Key（如 `nginx.conf`）、名称、分类、采集命令（SSH，留空自动匹配内置模板）

2. **用模板建基线**
   - 在「采集模板」Tab 卡片点「用此模板建基线」快速预填

### 看到什么
- 配置基线列表，含目标资产、配置项、采集命令、创建时间

## 第二步：检测漂移

### 操作页面
**资源管理** → **资产管理** → **配置漂移检测** → **配置基线** Tab

### 操作步骤

## 第三步：AI 评估与状态处理

### 操作页面
**资源管理** → **资产管理** → **配置漂移检测** → **漂移记录** Tab

### 操作步骤

1. **AI 评估**
   - 漂移记录「查看评估」→ AI 评估抽屉显示：根因、影响、建议修正方案、变更风险评估、处置建议（应用修正/人工复核/忽略）

### 看到什么
- 漂移记录列表（按状态/严重度着色）与 AI 评估报告

### 结果
配置漂移闭环：采集基线 → 定期重采 → 漂移判定 → AI 评估 → 处置闭环。

# 链路27：沙盒管控 与 知识图谱推理

## A. 沙盒管控

> 入口：**Agent 管理 → Agent 运维 → 沙盒管控**（key=`sandbox-overview`，path=`/sandbox`）。含「全局配置 / 策略管理 / 决策测试 / 执行日志」四个 Tab。

### 第一步：配置全局策略

**Agent 管理 → Agent 运维 → 沙盒管控 → 全局配置** Tab
- 沙盒总开关、干运行（dry-run）模式、单会话与单日最大执行次数、允许最大风险等级、写操作时间窗口
- 改动即自动保存 → POST `/sandbox/api/config`

### 第二步：管理策略（黑白名单 + 目录范围）

**沙盒管控 → 策略管理** Tab
1. 「新建策略」→ 配置：作用范围（全局/角色/用户/会话 + scope_id）、资产白/黑名单、工具白/黑名单、允许/禁止命令规则、**允许目录范围**、最大风险等级、每日执行次数、启用
2. 支持编辑/删除
- **允许目录范围**：逗号分隔路径列表（如 `/data/aiops,/tmp`）；AI 命令 `cd` 到范围外或写绝对路径落到范围外将被拦截

### 第三步：决策测试

**沙盒管控 → 决策测试** Tab
- 填：动作类型/工具名/资产 ID/命令/风险等级/用户角色 ID →「测试决策」→ POST `/sandbox/api/evaluate`
- 返回 `allowed` 与原因（命中哪条策略/规则）

### 第四步：执行日志

**沙盒管控 → 执行日志** Tab
- 查看每次执行的 动作/工具/风险/模式（dry_run | live）/决策/拒绝原因

### 沙盒与 AI 能力中心的安全配合
- 沙盒「允许目录范围」限制 AI 的作用目录；Agent 能力中心的「提议-确认闭环」「内部工具隔离」「风险等级只升不降」与之互补

## B. 知识图谱推理

> 入口：**知识库 → 知识管理 → 知识图谱推理**（key=`graph-inference`，path=`/knowledge/graph-inference`）。含「故障传播分析 / 根因定位推理 / 知识推荐推理」三个 Tab。

### 第一步：故障传播分析

**知识图谱推理 → 故障传播分析** Tab
- 选故障源资产 + 传播深度（1-5 层）→「开始推理」→ GET `/knowledge/graph/api/impact-analysis`
- 结果：受影响资产列表、传播路径、智能建议、高影响/已触发告警统计

### 第二步：根因定位推理

**知识图谱推理 → 根因定位推理** Tab
- 填告警 ID（逗号分隔，留空取最近 24h）+ 时间范围 →「开始推理」→ POST `/knowledge/graph/api/root-cause`
- 返回根因候选（融合 PageRank/入度/告警传播 + 综合评分 + 置信度）+ 推理依据 + 拓扑路径

### 第三步：知识推荐推理

**知识图谱推理 → 知识推荐推理** Tab
- 填告警 ID 或资产 ID + 推荐数 →「开始推理」→ GET `/knowledge/graph/api/recommend`
- 返回关联推理路径 + 推荐结果（Runbook / 知识库 / 历史 RCA / 相似故障，按评分排序）

### 结果
图谱推理闭环：拓扑关系 → 影响传播分析 → 根因定位 → 知识推荐。

# 链路28：SOP 工作流引擎

> 入口：**运维工作台 → 流程引擎**（含「工作流模板」「工作流执行」两个子菜单）。

## 第一步：创建工作流模板

### 操作页面
**侧边栏** → **运维工作台** → **流程引擎** → **工作流模板**

### 操作步骤

1. **新建模板**
   - 点击「+ 新建模板」→ 填写：名称、分类（generic/disk/service/k8s/database/network/security 等）、**触发类型（manual / alert_auto / scheduled）**、风险等级、描述、触发条件（JSON）、节点定义（JSON 数组）、边定义（JSON，依赖关系）、启用
   - 保存 → POST `/workflow/api/templates/create`

2. **为模板配置触发方式**
   - `manual`：手动触发
   - `alert_auto`：告警自动触发
   - `scheduled`：cron 定时触发

### 看到什么
- 模板列表，含触发类型、风险等级、节点/边定义；节点可声明 `requires_confirm`（需人工确认）

---

**下一步：触发与执行** →

## 第二步：触发并执行工作流

### 操作页面
**运维工作台** → **流程引擎** → **工作流执行**

### 操作步骤

1. **触发工作流**
   - 点击「+ 触发工作流」→ 选择 SOP 模板（或「--自定义节点--」手工编辑远程命令节点）→ 填工作流标题 + 运行时上下文（JSON，如 `asset_id` / `alert_id` / `service_name`）→「触发」→ POST `/workflow/api/runs/create`

2. **运行时上下文注入**
   - 支持模板语法 `{{ context.probe.disk_usage_pct }}` 自动注入探测值；`_` 前缀变量为平台保留

3. **监控与节点操作**
   - 执行中被拦截的节点（如 `requires_confirm`）→「确认执行 / 取消」
   - 失败节点「重试」；执行中「中止」→ POST `/workflow/api/runs/{id}/abort`

4. **查看详情**
   - 详情查看 上下文（用户输入/环境探测/内部变量）+ 节点执行状态流

### 看到什么
- 工作流执行列表（执行中/待确认/已完成/失败/已中止），5 秒自动轮询刷新
- 触发源（trigger_source）标记为 告警/定时/手动

### 结果
SOP 工作流闭环：模板化 SOP → 手动/告警/cron 触发 → 节点确认与执行 → 状态监控 → 结果审计。

## 链路28 补充：变更发布（蓝绿发布 & 变更审批）

> 入口：**运维工作台 → 变更发布**，含「蓝绿发布 / 变更审批」两个页面。

### A. 蓝绿发布

**侧边栏** → **运维工作台** → **变更发布** → **蓝绿发布**
1. **新建部署**：填名称/命名空间/K8s 集群/蓝标签/绿标签/蓝副本/绿副本/镜像 → POST `/blue-green/api/create`
2. **切换蓝绿**：确认后切换活跃/备用流量 → POST `/blue-green/api/{id}/switch`
3. **回滚**：切回上一次活跃版本 → POST `/blue-green/api/{id}/rollback`
4. **历史**：查看切换/回滚时间线 → GET `/blue-green/api/{id}/records`

### B. 变更审批（CAB 变更评审）

**侧边栏** → **运维工作台** → **变更发布** → **变更审批**
1. **新建变更**：填标题/描述/类型（normal/emergency/standard）/优先级/风险/CI 类型/计划时间 → POST `/change-workflow/api/create`
2. **审批流转**：草稿 → 提交审批 → 待审批 → 通过/驳回 → 开始执行 → 进行中 → 完成/回滚（action 参数 submit/approve/reject/start/complete/rollback）→ POST `/change-workflow/api/{id}/{action}`
3. **执行任务管理**：进行中动态添加执行任务（描述/命令/序号）、更新任务状态

### 看到什么
- 蓝绿发布部署卡片 + 切换/回滚时间线
- 变更审批表格 + 状态流转按钮 + 执行步骤列表

## 常见问题

### Q1：技能市场拉取失败？
- **检查**：是否有网络访问 GitHub；未认证限流 60/时 → 配置 GitHub Token

### Q2：组件部署失败？
- **检查**：目标机是否可达、SSH 凭据是否正确、磁盘/内存是否充足
- **检查**：需要外网或私有镜像源时，是否正确配置网络代理/镜像仓库

### Q3：配置漂移检测无结果？
- **检查**：是否有对应基线；采集命令是否为可执行 SSH 命令
- **检查**：目标资产是否在线、凭据是否正确

### Q4：沙盒决策被拦截？
- **检查**：命中哪条策略/规则（决策测试返回 reason）
- **检查**：命令 `cd` 或绝对路径是否落在「允许目录范围」外

### Q5：知识图谱推理结果为空？
- **检查**：是否建立了资产关系/拓扑数据（关系图无节点则无传播路径）
- **检查**：告警/资产 ID 是否正确；是否在查询时间窗口内

### Q6：工作流执行卡在待确认？
- **检查**：节点是否声明了 `requires_confirm`（需人工在详情点「确认执行」）
- **检查**：运行时上下文是否提供了节点所需参数
