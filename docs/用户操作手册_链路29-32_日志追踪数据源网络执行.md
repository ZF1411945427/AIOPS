# AIOps 用户操作手册 — 链路29-32：日志追踪 & 数据源 & 网络测试 & 执行编排报表

> **适用角色**：SRE、运维工程师、数据分析师
> **前置条件**：已登录系统，拥有相关菜单权限
> **预计耗时**：约 25-35 分钟

---

## 概述

本手册覆盖四条链路（补齐监控与执行工具类功能页）：

- **链路29**：日志中心 + 链路追踪 + 接入指引
- **链路30**：数据源管理
- **链路31**：网络测试
- **链路32**：远程脚本 + Ansible 编排 + 运维报表

> **链路29 日志追踪**　①日志中心 → ②AI日志分析 → ③链路追踪 → ④接入指引
> **链路30 数据源**　①新增数据源 → ②测试/启用 → ③设为默认
> **链路31 网络测试**　①Ping → ②端口 → ③DNS/HTTP/TLS/归属地
> **链路32 执行报表**　①远程脚本 → ②Ansible → ③运维报表

# 链路29：日志中心 & 链路追踪

## 第一步：日志中心

### 操作页面
**侧边栏** → **智能分析室** → **日志分析** → **日志中心**

### 操作步骤

1. **搜索日志**
   - 顶部选择数据源（`sourceId`）、输入搜索词、选择时间范围
   - 点「搜索」→ GET `/logs/api/search`
   - 默认折叠相邻重复日志（降噪），勾选「显示原日志」可看原始日志

2. **高级过滤**
   - 展开过滤区：业务域、索引、级别、主机、服务、应用 → 点「应用」

3. **AI 分析日志**
   - 勾选日志 → 点「AI 分析选中日志」→ 抽屉内填诉求 →「开始分析」→ POST `/ai-insight/analyze`（source_type=logs）
   - 分析结果下点「转交执行 → 智能助手」→ 跳转 AI 助手继续处理

4. **日志告警规则**
   - 展开告警规则面板 →「+ 新建」→ 填规则 → 创建
   - 每条规则可启用/禁用、删除

5. **查看历史**
   - 点「历史」查看/删除 AI 分析历史

### 看到什么
- 日志结果列表（按时间倒序、级别着色）
- AI 分析抽屉（聚类摘要/问题/建议）与历史记录

## 第二步：链路追踪

### 操作页面
**侧边栏** → **智能分析室** → **链路追踪** → **链路追踪**

### 操作步骤

1. **查询链路**
   - 设置过滤：业务域、服务、关键词、状态、最小时长、条数 → 点「查询」→ GET `/api/traces`

2. **查看 Trace 详情**
   - 点击左侧某条 Trace → 右侧详情卡，含 3 个 Tab：**瀑布图 / 拓扑图 / Span 详情**
   - 瀑布图点某 Span → Span 详情 Tab 查看 Tags

3. **AI 链路分析**
   - 点「AI 链路分析」→ 填提问 →「开始分析」→ POST `/ai-insight/analyze`（source_type=traces，自动取 top20 异常/慢链路）
   - 结果下「转交执行 → 智能助手」→ 跳转 AI 助手

4. **历史与刷新**
   - 「历史」查看分析历史；「刷新」重新拉取

### 看到什么
- 统计卡（调用链数/服务数/平均耗时/错误率）
- 详情卡瀑布图/拓扑图/Span 详情

## 第三步：接入指引

### 操作页面
**侧边栏** → **智能分析室** → **链路追踪** → **接入指引**

### 操作步骤

1. **查看接入状态**
   - 顶部卡片显示 span 总数、调用链数、已接入服务、最近数据 → GET `/api/v1/traces/ingest-status`

2. **获取 OTLP 端点**
   - 复制 OTLP 接收端点地址 → GET `/api/v1/traces/agent-guide`

3. **按语言/环境选择接入方式**
   - 切换服务类型 Tab：java / python / go / nodejs / k8s / docker / middleware / traditional
   - 每步点「复制」获取对应代码/配置

### 看到什么
- 接入状态卡 + 协议警告横幅 + OTLP 端点 + 各语言接入步骤指引
- 已配置的链路追踪数据源列表（Jaeger/OTel）

# 链路30：数据源管理

## 操作页面
**侧边栏** → **智能分析室** → **日志分析** → **数据源管理**

## 操作步骤

1. **新增数据源**
   - 点「+ 新增数据源」→ 填名称、类型、地址、认证方式、认证配置、SSH/K8s 额外配置、采集间隔 → 保存
   - 认证方式按类型动态显示：basic（用户名/密码）、bearer（Token）、api_key（Key/Value）、ssh、kubernetes

2. **测试连接**
   - 列表「测试」→ POST `/datasources/api/{id}/test`

3. **启用 / 停用**
   - 列表「启用/停用」→ POST `/datasources/api/{id}/toggle`

4. **设为默认**
   - 「设为默认」→ 设为日志中心默认数据源

5. **编辑 / 删除**
   - 编辑：先 GET 详情并处理敏感字段（密码/Token 返回 `***`）
   - **敏感字段契约**：编辑时置空、保存时空值=不更新，避免用 `***` 覆盖真值

## 看到什么
- 数据源列表（类型/认证/状态/采集间隔/最后采集/日志默认）
- 敏感字段全程掩码处理

# 链路31：网络测试

## 操作页面
**侧边栏** → **运维工作台** → **工具箱** → **网络测试**

## 操作步骤

> ⚠️ 合规约束：仅可测自有资产、不批量扫端口、限频 1 次/秒。可用「资产快选」下拉从资产列表选 IP 自动填入目标。

1. **Ping**：填目标 → 执行 → POST `/api/network-test/ping`
2. **Traceroute**：填目标 → 执行 → POST `/api/network-test/traceroute`
3. **TCP 端口**：填目标+端口（可点常用端口标签）→ 执行 → POST `/api/network-test/tcp-port`
4. **DNS**：填域名+记录类型（A/AAAA/CNAME/MX/NS/TXT/PTR）→ 执行 → POST `/api/network-test/dns`
5. **HTTP/HTTPS**：填 URL+方法（GET/HEAD）→ 执行 → POST `/api/network-test/http`（显示响应头/体预览）
6. **TLS 证书**：填域名+端口 → 执行 → POST `/api/network-test/tls-cert`（显示剩余天数）
7. **IP 归属地**：填 IP → 执行 → POST `/api/network-test/ip-location`（国家/地区/城市/ISP）

## 看到什么
- 各 Tab 独立执行结果面板，展示响应数据与耗时

# 链路32：远程脚本 & Ansible 编排 & 运维报表

## 第一步：远程脚本

### 操作页面
**侧边栏** → **运维工作台** → **工具箱** → **远程脚本**

### 操作步骤

1. **执行脚本**
   - 选目标主机（来自资产）→ 填脚本内容 + 超时秒（FormData 传 `target_id`/`script_content`/`timeout`）→ 点「执行」→ POST `/script/api/execute`

2. **生成 Playbook**
   - 在最新执行结果区点「📦 生成 Playbook」→ 弹窗自动把脚本命令转为 Ansible shell 模块 YAML
   - 「复制 YAML」或「保存并跳转 Ansible」→ POST `/ansible/api/playbooks`

3. **查看历史**
   - 历史列表点「查看」展开脚本/STDOUT/STDERR；分页浏览

## 看到什么
- 执行结果面板（STDOUT / STDERR）+ 生成 Playbook 入口 + 历史记录

---

## 第二步：Ansible 编排

### 操作页面
**侧边栏** → **运维工作台** → **工具箱** → **Ansible 编排**

### 操作步骤

1. **执行历史 Tab**：点「+ 执行」→ 选清单 + Playbook + 额外变量 JSON → 执行 → POST `/ansible/api/run`

2. **主机清单 Tab**：
   - 「+ 新建清单」→ 或「从资产选择生成」→ 勾选资产（server/virtual_machine/cloud_host）→ 生成 YAML → 保存
   - 「测试」→ POST `/ansible/api/test-inventory`（弹出连接结果）

3. **Playbook 模板 Tab**：「+ 新建 Playbook」→ 编辑 YAML → 保存；可编辑/删除

4. **查看/删除**：执行历史/清单/Playbook 均可查看、删除

## 看到什么
- 3 个 Tab（执行历史/主机清单/Playbook 模板）+ Ansible 安装状态标签
- 执行结果对话框（ID/清单/Playbook/状态/退出码）

---

## 第三步：运维报表

### 操作页面
**侧边栏** → **运维工作台** → **工具箱** → **运维报表**

### 操作步骤

1. **生成报表**
   - 列表页点「生成日报 / 周报 / 月报」→ POST `/reports/api/generate/{type}`（type=daily/weekly/monthly）

2. **查看详情**
   - 点报表卡片 → 详情视图：运营总评横幅（等级 A/B/C/D）、6 个统计卡、告警趋势折线图、告警级别分布饼图、高频告警指标 TOP、告警最多资产 TOP、受影响资产表、评估与建议

3. **导出 / 删除**
   - 详情点「导出 HTML」→ GET `/reports/api/{id}/export`
   - 列表卡片右上角 × → 删除

## 看到什么
- 报表卡片网格（类型/标题/周期/摘要）+ 详情页图表与评估建议

## 常见问题

### Q1：日志搜索无结果？
- **检查**：数据源是否正确配置并启用
- **检查**：时间范围是否正确；是否被降噪折叠（勾「显示原日志」）

### Q2：链路追踪无数据？
- **检查**：应用是否已接入（见接入指引）并上报 span
- **检查**：过滤条件（服务/状态/时间）是否正确

### Q3：数据源测试失败？
- **检查**：地址/端口是否可达、认证凭据是否正确
- **检查**：敏感字段是否被 `***` 覆盖（编辑时需重新输入）

### Q4：Ansible 执行失败？
- **检查**：Ansible 是否安装（看安装状态标签）
- **检查**：主机清单（inventory）与目标主机连通性；Playbook 语法
