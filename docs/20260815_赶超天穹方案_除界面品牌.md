# 智渊 AIOps 赶超天穹方案（界面/品牌除外）

> 创建日期: 2026-08-15
> 目标: 让智渊在**功能广度 / AI 智能体能力 / AI 自主执行深度 / 组件对话管控覆盖**四项上赶超炎龙天穹。
> 排除: 界面体验 / 对外品牌 / 官网（用户明确不在此次范围）。
> 当前基线: LLM 工具 50 个、组件类工具 category 16 类、组件商店 54 组件、技能 14 个、Trivy/四合一体检已有、配置漂移已有。

## 二、P0：组件对话管控覆盖拉满（最大短板）

**现状**: 16 组件类已有工具, 但以下常见组件缺专门对话诊断工具(只靠 SSH 通用纳管, 无"AI 对话式"体验)。

### 新增组件对话工具(追加到 component_mcp_tools.py, 全部只读+expose_to_llm)

| # | 组件 | 工具名 | 能力(只读诊断) |
|---|---|---|---|
| 1 | MariaDB | mariadb_diagnose | 慢查询/连接/复制(复用 mysql 逻辑) |
| 2 | TiDB | tidb_diagnose | 集群/region/慢语句 |
| 3 | MinIO | minio_diagnose | 桶/对象/健康(S3 API) |
| 4 | Valkey/Redis集群 | valkey_diagnose | 集群槽位/节点/内存 |
| 5 | EMQX | emqx_diagnose | MQTT 连接/消息/集群 |
| 6 | Consul | consul_diagnose | 服务/健康检查/raft |
| 7 | APISIX | apisix_diagnose | 路由/上游/节点 |
| 8 | Traefik | traefik_diagnose | 路由/后端/中间件 |
| 9 | Keycloak | keycloak_diagnose | 领域/客户端/会话 |
| 10 | Prometheus | prometheus_diagnose | 规则/目标/抓取/配置 |
| 11 | Grafana | grafana_diagnose | 数据源/面板/告警通道 |
| 12 | Loki | loki_diagnose | 存储/保留/摄取 |

**配套**: 每个新组件写 `skills/components/*/SKILL.md` 技能包(声明 tools_required), 让 Agent 主导调用。
**预期**: 组件类 category 16→**28+**, 对话工具 50→**62+**。

### 通用"组件对话操作闭环"
- 给组件商店每条**组件实例**注册一个实例级 MCP 工具 `component_ops`, 把 部署/配置/健康/漏洞/AI 封装成 Agent 可调工具。实现"一句话: 诊断这台 Redis 并优化配置"。

## 三、P0：AI 智能体能力升级（多专家 + 自主任务）

天穹主打"多智能体协同"。智渊目前是单助手+工具环。赶超方向:

### 1. AI 多专家编排(router + 子专家)
- 现有 `agent_service.py` 基础上, 引入**专家路由**：按提问领域(数据库/网络/K8s/安全/可观测)分派到对应"子专家"(复用已有的组件技能包/工具集)。
- 子专家 = 一组专业工具 + 专属 system prompt + 专属技能。用 `use_skill` 加载对应 SKILL.md。
- 界面: 智能助手左侧栏显示"当前专家"标签 + 可手动切换。

### 2. AI 自主任务规划(Plan-Execute)
- 现有 `sop`/`parse`(AI自动部署) 机制泛化: 提供"AI 自主任务"入口——用户一句话, AI 拆解成多步计划, 逐步执行并带验证/回滚(复用 deploy 的 L4/L5 引擎)。

### 3. AI 变更自动审批门
- 高风险写操作工具(remediation/config change)加 `review_gate=True`, 走审批流程后再执行。体现"AI 能干但管得住"(天穹宣传点)。

## 四、P1：AI 自主执行深度

### 1. AI 自愈编排升级
- 现有自愈流程基础上, 增加"**AI 自动触发**": 告警命中 → AI 判断根因 → 自动匹配预案执行 → 验证 → 记知识库。做成可配置开关(自动/半自动/人工确认)。

### 2. 批量组件生命周期(定时巡检 + 自动体检)
- 组件商店支持**批量**对多个实例执行"定时四合一体检", 生成巡检报告(复用 inspection 调度)。

### 3. 对话式运维沙箱
- 智能助手支持"**演练模式**": AI 先生成命令/改动的预览,dry-run 确认后再执行(提高信任度, 对标天穹可控性)。

## 五、P1：功能广度补齐（随以上同步）

- 长尾组件(信创 DM/金仓/openGauss/OceanBase 已入库, 但缺专门对话工具)→ 归入 P0 工具扩展优先做信创 4 件。

## 六、里程碑与验收

| 阶段 | 交付 | 验收基准 |
|---|---|---|
| **M1** | 组件工具 16→28 类 + 12 个技能包 | `list_llm_tools` 组件类≥28; AI 可对话调用 MariaDB/TiDB/MinIO 等新工具 |
| **M2** | AI 多专家编排 + 专家路由 | 智能助手按领域分派子专家; 界面显示专家标签 |
| **M3** | AI 自主任务(Plan-Execute 泛化) + 审批门 | 一句话触发多步自主任务; 高危写操作需审批 |
| **M4** | AI 自愈编排 + 批量定时体检 + 演练沙箱 | 告警自动触发自愈(可配置); 批量体检报告 |

**质量门禁**: 每项完成后 后端 /healthz + 相关接口 200 + 前端 build 通过 + 组件类工具注册验证 + CONTRACT 同步 + 多轮自测(service mock + HTTP 端到端)。

## 附：一句作战口号

> 天穹靠"50 组件对话 × 多智能体宣传"取胜 —— 智渊用**更深的多专家编排(面向真实 LLM 落地) + 更全的组件对话工具(28+ 类) + 更强的自主执行闭环(L4/L5 部署/自愈/审批门)** 反超, 并叠加 SRE/移动端/离线交付这些天穹根本没有的护城河。广度、智能、深度三维全面压过。
