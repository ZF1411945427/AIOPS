# 链路45：多集群管理 & Edge 升级 & 网络设备

## 第一步：多集群管理

### 操作页面
**侧边栏** → **系统配置** → **系统管理** → **多集群管理**

### 操作步骤

1. **注册集群**
   - 「+ 注册集群」→ 填集群名、角色（controller/node）、关联 K8s DataSource、数据面状态、遥测通道、版本等 → POST `/api/k8s-clusters`

2. **管理集群**
   - 每行操作：👁️ 遥测详情、✅ 数据面检查、✏️ 编辑、🗑️ 删除
   - 顶部「🔄 刷新检查」刷新

### 看到什么
- 统计卡（集群总数/controller/node/active 数据面）+ 集群表格 + 遥测详情弹窗

---

## 第二步：Edge 升级

### 操作页面
**侧边栏** → **系统配置** → **系统管理** → **Edge 升级**

### 操作步骤

1. **新建升级任务**
   - 「+ 新建升级任务」→ 填目标版本、关联集群、策略（batch 分批 / all_at_once），batch 可设每批数量 → POST `/api/upgrade-jobs`

2. **管理任务**
   - 卡片操作：▶️ 执行（状态需 pending/failed/paused）、⏸ 暂停、👁️ 步骤详情、🗑️ 删除
   - 状态机：pending/running/paused/completed/failed/rolled_back

### 看到什么
- 统计卡（任务/已完成/失败回滚/进行中）+ 任务卡片列表（进度条/策略/日志）

---

## 第三步：网络设备

### 操作页面
**侧边栏** → **系统配置** → **系统管理** → **网络设备**

### 操作步骤

1. **添加设备**
   - 「+ 添加设备」→ 填名称、管理 IP、类型、SNMP 版本（v1/v2c）、Community、端口、厂商型号 → POST `/api/network/devices`

2. **设备操作**
   - 行操作：🔍 连通校验（validate）、📊 接口轮询（poll）、🕸️ 邻居发现（discover）、👁️ 详情、🗑️ 删除

3. **主机链路映射**
   - 「🔗 主机链路映射」→ 输入主机 IP 反查接入的交换机端口 → POST `/api/network/map-links`

### 看到什么
- 统计卡（设备/可达/不可达）+ 设备表格 + 详情（接口/邻居）+ 主机链路映射弹窗

# 链路46：事件统计收敛 & 事件源配置 & 可观测关联

## 第一步：事件统计与告警收敛

### 操作页面
**侧边栏** → **值班驾驶舱** → **告警响应** → **统计收敛**

### 操作步骤

1. **事件统计 Tab**
   - 统计卡（总事件/警告/严重/普通）+ 资源类型分布 + 原因分布 → GET `/events/api/stats`

2. **告警收敛闭环 Tab**
   - 总结卡（活跃告警/资产/聚类/耗时）+ 严重度分布 + 聚类明细（服务/时间窗/拓扑 子 Tab）
   - 点某聚类「详情」→ 看根因推荐、影响分析、告警列表 → GET `/api/alert-correlation/clusters/{id}`
   - 「刷新」/「强制刷新缓存」

### 看到什么
- 2 个 Tab（事件统计 / 告警收敛闭环）+ 聚类详情弹窗

---

## 第二步：事件源配置

### 操作页面
**侧边栏** → **智能分析室** → **事件管理** → **事件源配置**

### 操作步骤

1. **新增事件源**
   - 「+ 新增事件源」→ 填名称、类型（Zabbix/Prometheus/Webhook/通用）、API URL、同步间隔、认证 JSON → POST `/event-sources/api/create`

2. **管理事件源**
   - 卡片操作：启用/禁用（toggle）、同步（sync，拉取外部告警）

### 看到什么
- 事件源卡片列表（名称/类型/启用/API URL/同步间隔/上次同步）

---

## 第三步：可观测关联

### 操作页面
**侧边栏** → **智能分析室** → **关联分析** → **日志·指标·链路关联**

### 操作步骤

1. **查询全域关联**
   - 选时间范围/服务/资产 → 点「查询」→ 加载全域分析（告警/指标/日志/链路/关联资产/多信号资产）

2. **联动过滤**
   - 点击时间轴泳道或拓扑节点 → 联动过滤（拓扑节点点击设为 service 并重查）

3. **AI 深度分析**
   - 「AI 深度分析」→ POST 后跳转 AI 助手会话 → POST `/agent/correlation-analyze`

4. **查看详情**
   - 详情 Tab（告警/指标异常/日志异常/链路异常/关联资产）；链路异常点「详情」看 trace/span

### 看到什么
- RCA 建议条 + 概览统计卡 + 信号时间轴 + 服务拓扑 + 详情 Tab

# 链路47：混沌实验报告 & 场景库

## 第一步：混沌实验报告

### 操作页面
**侧边栏** → **可靠性工程** → **混沌工程** → **实验报告**

### 操作步骤

1. **查看整体概览**
   - 统计卡（总运行/通过/失败/触发告警）+ 韧性雷达图 + 故障类型分布饼图 → GET `/api/chaos/summary`、`/resilience-radar`

2. **分析运行记录**
   - 实验运行记录表（稳态验证/告警/预算消耗/实验前后可用性）
   - 失败实验分析表定位韧性短板

### 看到什么
- 统计卡 + 雷达图 + 饼图 + 运行记录 + 失败实验分析

---

## 第二步：混沌场景库

### 操作页面
**侧边栏** → **可靠性工程** → **混沌工程** → **场景库**

### 操作步骤

1. **筛选场景**
   - 层级筛选：全部 / 主机VM / 容器 / K8s校排 / 网络

2. **一键创建实验**
   - 点卡片或「一键创建实验」→ 预填 `chaos_prefill` 并跳转至「混沌实验」页

3. **自定义场景**
   - 「+ 自定义场景」→ 填名称/层级/故障类型/风险等级/推荐 SLO → 创建；非内置可删除

### 看到什么
- 场景卡片网格（风险标签/层级/故障类型/推荐 SLO/操作）

# 链路48：实时监控看板 & 架构巡检图

## 第一步：实时监控看板

### 操作页面
**侧边栏** → **值班驾驶舱** → **监控总览** → **实时监控看板**

### 操作步骤

1. **查看实时监控**
   - 选资产 + 时间范围（1h~30d）→ 自动重查 → GET `/api/dashboard/data?time_range=&asset_id=`
   - 统计卡（资产/在线/活跃告警/健康分/规则/未关闭事件/数据源）

2. **大图与图表**
   - CPU/内存/磁盘表盘 + 系统负载、网络流/告警趋势/健康评分、资产类型/告警级别分布、最新告警表

3. **自动刷新 / 全屏**
   - 开「自动刷新」每 15s 刷新；点全屏图标切换浏览器全屏

### 看到什么
- 统计卡 + 表盘大图 + 各趋势/分布图表 + 最新告警表

---

## 第二步：架构巡检图

### 操作页面
**侧边栏** → **值班驾驶舱** → **监控总览** → **架构巡检图**

### 操作步骤

1. **总览模式**
   - 统计卡 + 搜索框 + 业务域卡片网格 → GET `/health-map/api/domains`
   - 点某业务域卡片进入该域详情

2. **域详情模式**
   - 返回条 + 业务域切换 + 实体搜索 + 架构拓扑图（ECharts 分层卡片 + 调用连线）
   - 点拓扑节点打开实体详情抽屉（基础/链路指标/基础设施/父级子级/活跃告警/最近指标）

3. **生成架构图**
   - 「生成架构图」→ 配置导出格式（drawio/png/svg/pdf）、AI 智能布局、draw.io 本地路径、实时绘制 → POST `/api/arch-diagram/generate`

### 看到什么
- 两模式（总览/详情）+ 架构拓扑图 + 实体详情抽屉 + 生成架构图弹窗

## 常见问题

### Q1：网络设备 poll 无数据？
- **检查**：SNMP 版本/Community 是否正确、设备是否可达、端口是否开放（UDP 161）

### Q2：事件源同步失败？
- **检查**：API URL 是否可达、认证 JSON 是否正确
- **检查**：类型（Zabbix/Prometheus/Webhook/通用）对接方式是否匹配

### Q3：混沌实验报告为空？
- **检查**：是否已有实验运行记录（未运行过则无统计）

### Q4：架构巡检图无拓扑？
- **检查**：是否存在资产/业务域数据；拓扑连线需服务调用数据
